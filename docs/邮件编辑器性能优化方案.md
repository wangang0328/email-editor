## 2. 核心瓶颈分析

### 2.1 渲染管线耗时分解（L 档）

| 阶段 | 耗时 | 占比 | 优化潜力 |
|------|------|------|----------|
| `JsonToMjml` (renderToStaticMarkup) | ~150ms | 20% | ★★★ 块级缓存 |
| `mjml-browser` 编译 | ~200ms | 26% | ★★ Worker 卸载 |
| `htmlToReact` | ~5ms | <1% | ★ 扁平化 |
| `cloneDeep` (多处) | ~10ms | 1% | ★ 结构共享 |
| Preview 管线冗余 | ~300ms | 40% | ★★★ 按需计算 |
| React commit | ~100ms | 13% | ★★ 增量更新 |

### 2.2 问题根因

1. **双管线同步执行**：编辑 Tab 下 Preview 管线无必要立即执行
2. **全量重算**：任意变化触发整棵树 JsonToMjml + mjml 编译
3. **无缓存机制**：相同内容重复计算（如 Undo→Redo→Undo）
4. **主线程阻塞**：编译在主线程执行，形成 Long Task
5. **深拷贝过多**：多处 `cloneDeep` 叠加

## 3. 场景 1：冷启动优化

### 3.1 当前数据

| 档位 | `initialRender.totalMs` | `pipelineMs` | `canvasReady` |
|------|------------------------|--------------|---------------|
| S (472) | 302-330ms | 35-59ms | 565-684ms |
| M (775) | 408-434ms | 81-84ms | 779-832ms |
| L (817) | 789-842ms | 266-283ms | 1411-1523ms |

### 3.2 优化方案

#### P0-1: 首屏骨架屏 + 渐进渲染

**问题**：用户等待 1.4s+ 才能看到可交互画布

**方案**：
```tsx
// EmailEditor/index.tsx
function EmailEditor() {
  const [isReady, setIsReady] = useState(false);

  return (
    <>
      {!isReady && <EditorSkeleton />}
      <div style={{ visibility: isReady ? 'visible' : 'hidden' }}>
        <MjmlDomRender onReady={() => setIsReady(true)} />
      </div>
    </>
  );
}
```

**预期**：视觉响应时间从 1.4s → <200ms

#### P0-2: 预览管线延迟初始化 --- 已完成

**问题**：初次加载时双管线同时执行

**方案**：
```tsx
// PreviewEmailProvider/index.tsx
const { activeTab } = useActiveTab();
const [initialized, setInitialized] = useState(false);

useEffect(() => {
  // 首次切到预览 Tab 时才初始化管线
  if (activeTab !== ActiveTabKeys.EDIT && !initialized) {
    setInitialized(true);
  }
}, [activeTab]);

useEffect(() => {
  if (!initialized) return; // 编辑 Tab 下跳过
  // 现有管线逻辑...
}, [lazyPageData, initialized]);
```

**预期**：初始 `canvasReady` 从 1449ms → ~900ms（节省 ~500ms）

#### P1-1: JsonToMjml SSR 缓存

**问题**：每次加载同一模板都重新计算

**方案**：服务端预渲染 MJML，客户端缓存命中时直接使用

```ts
// 服务端 API
interface TemplateCache {
  templateId: string;
  contentHash: string;
  editMjml: string;
  editHtml: string;
  previewHtml: string;
}

// 客户端
const cachedHtml = await fetchTemplateCache(templateId, contentHash);
if (cachedHtml) {
  // 跳过 JsonToMjml + mjml 编译
  setHtml(cachedHtml);
}
```

**预期**：二次加载 `pipelineMs` 从 ~283ms → ~5ms

#### P1-2: Web Worker 编译

**问题**：mjml-browser 编译阻塞主线程

**方案**：
```ts
// mjmlWorker.ts
import mjml from 'mjml-browser';

self.onmessage = (e) => {
  const { mjmlString, id } = e.data;
  const html = mjml(mjmlString).html;
  self.postMessage({ html, id });
};

// MjmlDomRender.tsx
const worker = useMemo(() => new Worker('./mjmlWorker.ts'), []);
```

**预期**：主线程 Long Task 从 ~800ms → <200ms

## 4. 场景 2：富文本输入优化

### 4.1 当前数据

| 档位 | 管线触发次数 | `pipelineMs` 中位数 | `pipelineMs` 最大值 |
|------|-------------|--------------------|--------------------|
| S (472) | 0 | 21.8ms | 39.8ms |
| M (775) | 0 | 46.4ms | 93.5ms |
| L (817) | 0 | 291.4ms | 310.5ms |

> 注：管线触发 0 次是因为富文本聚焦时 `MjmlDomRender` 跳过同步；但 `PreviewEmailProvider` 仍会触发

### 4.2 优化方案

#### P0-1: Preview 管线 debounce 增大

**问题**：当前 debounce 0ms，每次输入都触发 ~300ms 管线

**方案**：
```tsx
// PreviewEmailProvider/index.tsx
// 改动前
const lazyPageData = useLazyState(pageData, 0);

// 改动后：编辑 Tab 下 debounce 500ms
const { activeTab } = useActiveTab();
const isEditTab = activeTab === ActiveTabKeys.EDIT;
const lazyPageData = useLazyState(pageData, isEditTab ? 500 : 0);
```

**预期**：输入 20 字时 preview 管线触发从 ~20 次 → 1-2 次

#### P0-2: 富文本输入时完全跳过 Preview

**问题**：用户输入时不看预览，无需实时计算

**方案**：
```tsx
// 检测富文本编辑状态
const isTextEditing = useIsTextEditing(); // 监听 contenteditable focus

useEffect(() => {
  if (isEditTab && isTextEditing) return; // 输入时跳过
  // 管线逻辑...
}, [lazyPageData, isEditTab, isTextEditing]);
```

**预期**：输入过程中 preview `pipelineMs` = 0

#### P1-1: 文本块局部更新

**问题**：改一个文本块，整棵树 JsonToMjml

**方案**：文本块变更时仅更新对应 DOM 节点，不触发完整管线

```tsx
// 文本块变更检测
const textOnlyChange = detectTextOnlyChange(prevContent, nextContent);

if (textOnlyChange) {
  // 直接更新 contenteditable 内容，跳过管线
  updateTextNodeDirectly(textOnlyChange.idx, textOnlyChange.newText);
} else {
  // 完整管线
  runFullPipeline();
}
```

**预期**：文本输入 `pipelineMs` 从 ~291ms → 0

## 5. 场景 3：属性面板修改优化

### 5.1 当前数据

| 档位 | 管线触发次数 | `pipelineMs` 中位数 | `formState.change` |
|------|-------------|--------------------|--------------------|
| S (472) | 5 | 35.1ms | 37.9 |
| M (775) | 5 | 49.8ms | 88.2 |
| L (817) | 5 | 294.4ms | 389.3 |

> **改造后（2026-06-18，L 档改 1 段颜色）**：`pipelineMs` **13.2ms**，compile+mount **~20ms**（L2 `directPatch`）。详见 [§5.3](#53-已落地优化与实测2026-06-18)。

### 5.2 优化方案

#### P0-1: 属性修改 debounce

**问题**：每次改色都触发完整管线

**方案**：
```tsx
// 属性面板组件
const debouncedChange = useMemo(
  () => debounce((value) => {
    form.change(fieldName, value);
  }, 150),
  [form, fieldName]
);

// 颜色选择器拖动时用 debounce
<ColorPicker onChange={debouncedChange} />
```

**预期**：连续改色 5 次，管线触发从 5 次 → 1-2 次

#### P0-2: 编辑 Tab 下跳过 Preview 管线

**问题**：属性修改时 Preview 同步触发（~300ms）

**方案**：复用场景 2 的 P0-1 方案

**预期**：单次属性修改从 ~600ms → ~300ms

#### P1-1: 样式属性局部更新

**问题**：改背景色触发整棵树重渲染

**方案**：样式类属性直接修改 DOM style，不触发管线

```tsx
const styleOnlyChange = detectStyleOnlyChange(prevContent, nextContent);

if (styleOnlyChange) {
  // 直接操作 Shadow DOM 内对应节点的 style
  const node = shadowRoot.querySelector(`[data-node-idx="${styleOnlyChange.idx}"]`);
  node.style[styleOnlyChange.prop] = styleOnlyChange.value;

  // 延迟同步到 MJML（用户停止操作后）
  debouncedSyncToMjml();
} else {
  runFullPipeline();
}
```

**预期**：样式修改 `pipelineMs` 从 ~294ms → ~5ms

> **注（2026-06-18）**：未采用「直接改 DOM style」方案；已通过 **L2 段级直通挂载**（`segmentPatches` + `postProcess.segment`）在架构层达成同等目标，且与 MJML/预览一致。详见 [编辑画布-L2段级直通挂载方案.md](./编辑画布-L2段级直通挂载方案.md)。

## 6. 场景 4：块操作优化

### 6.1 当前数据（L 档）

| 操作 | `useBlock.total` | `MjmlDomRender.pipeline` | `PreviewEmail.pipeline` |
|------|-----------------|-------------------------|------------------------|
| addBlock | 0.4ms | **504.7ms** | 344.5ms |

| copyBlock | 0.9ms | **467.3ms** | 323.8ms |
| removeBlock | 0.9ms | **477.7ms** | 305.2ms |

### 6.2 优化方案

#### P0-1: 编辑 Tab 下跳过 Preview 管线

**问题**：每次块操作触发 ~340ms Preview 管线

**方案**：复用场景 2/3 的方案

**预期**：块操作总耗时从 ~850ms → ~500ms

#### P0-2: startTransition 降级

**问题**：~500ms 同步任务阻塞 UI

**方案**：
```tsx
// useBlock.ts
import { startTransition } from 'react';

const addBlock = useCallback((params) => {
  startTransition(() => {
    // 现有添加块逻辑
    const newContent = cloneDeep(content);
    // ...
    form.change('content', newContent);
  });
}, [content, form]);
```

**预期**：Long Task 拆分，UI 更可响应

#### P1-1: 块级增量渲染

**问题**：添加一个块，整棵树 JsonToMjml

**方案**：
```tsx
// 变更检测
const changedBlocks = diffPageData(prevContent, nextContent);
// 返回: [{ idx: 'content.children.5', type: 'add', block: {...} }]

// 增量渲染
function incrementalRender(changes: BlockChange[]) {
  for (const change of changes) {
    if (change.type === 'add') {
      // 仅对新块跑 JsonToMjml
      const blockMjml = JsonToMjml({ data: change.block, idx: change.idx, ... });
      const blockHtml = mjml(blockMjml).html;
      insertBlockHtml(change.idx, blockHtml);
    } else if (change.type === 'remove') {
      removeBlockDom(change.idx);
    } else if (change.type === 'move') {
      moveBlockDom(change.fromIdx, change.toIdx);
    }
  }
}
```

**预期**：块操作 `MjmlDomRender.pipeline` 从 ~500ms → <50ms

#### P1-2: 块 MJML 片段缓存

**问题**：移动/复制块时重新计算 MJML

**方案**：
```ts
const blockMjmlCache = new Map<string, { hash: string; mjml: string; html: string }>();

function getBlockMjml(block: IBlockData, idx: string) {
  const hash = hashObject(block);
  const cacheKey = `${idx}:${hash}`;

  if (blockMjmlCache.has(cacheKey)) {
    return blockMjmlCache.get(cacheKey)!;
  }

  const mjml = JsonToMjml({ data: block, idx, ... });
  const html = mjmlCompile(mjml);
  blockMjmlCache.set(cacheKey, { hash, mjml, html });
  return { mjml, html };
}
```

**预期**：复制块 `pipelineMs` 从 ~467ms → ~10ms（缓存命中）

## 8. 场景 6：撤销/重做优化

### 8.1 当前数据（L 档）

| 操作 | `MjmlDomRender.pipeline` | `PreviewEmail.pipeline` |
|------|-------------------------|------------------------|
| Undo×3 | **472.4ms** | 304.4ms |
| Redo×2 | **459.7ms** | 289.3ms |

### 8.2 优化方案

#### P0-1: 编辑 Tab 下跳过 Preview 管线

**问题**：Undo 时 Preview 管线冗余执行

**方案**：复用场景 2/3/4 的方案

**预期**：Undo 从 ~770ms → ~470ms

#### P0-2: Undo/Redo HTML 缓存

**问题**：Undo/Redo 切换的都是历史快照，内容已知

**方案**：
```tsx
// RecordProvider.tsx
interface RecordEntry {
  template: IEmailTemplate;
  editHtml?: string;
  previewHtml?: string;
}

// 入栈时异步计算 HTML
const computeHtmlCache = async (template: IEmailTemplate) => {
  await new Promise(r => requestIdleCallback(r));
  const editMjml = JsonToMjml({ data: template.content, mode: 'testing', ... });
  const editHtml = mjml(editMjml).html;
  return { editHtml };
};

// Undo 时检查缓存
undo: () => {
  const entry = data[prevIndex];
  if (entry.editHtml) {
    // 跳过管线，直接使用缓存
    setCachedHtml(entry.editHtml);
  } else {
    form.reset(entry.template);
  }
}
```

**预期**：Undo `pipelineMs` 从 ~470ms → ~10ms

#### P0-3: startTransition 降级

**方案**：复用场景 4 的 P0-2 方案

#### P1-1: 连续 Undo 合并

**问题**：快速 Ctrl+Z×3 触发 3 次渲染

**方案**：
```tsx
const debouncedReset = useMemo(
  () => debounce((template) => form.reset(template), 16),
  [form]
);

undo: () => {
  const prevIndex = Math.max(0, index - 1);
  setIndex(prevIndex);
  debouncedReset(data[prevIndex]); // 合并多次调用
}
```

**预期**：连续 Undo×3 从 ~1400ms → ~500ms

## 9. 通用架构优化

### 9.1 减少 cloneDeep 调用

**当前问题点**：

| 位置 | 调用 | 可优化 |
|------|------|--------|
| MjmlDomRender | `contentSync.cloneDeep` | ✓ Undo/Redo 时跳过 |
| MjmlDomRender | `cloneDeep.mergeTags` | ✓ 引用传递 |
| PreviewEmailProvider | `cloneDeep.injectData` | ✓ 引用传递 |
| RecordProvider | `cloneDeep.values` | △ 需保留（快照） |
| useBlock | `*.cloneDeep` | ✓ Immer 替代 |

**方案**：
```tsx
// 用 Immer 替代 cloneDeep
import produce from 'immer';

// 改动前
const newContent = cloneDeep(content);
newContent.children.push(newBlock);
form.change('content', newContent);

// 改动后
const newContent = produce(content, draft => {
  draft.children.push(newBlock);
});
form.change('content', newContent);
```

### 9.2 htmlToReact 扁平化

**问题**：`RenderReactNode` 为每个 DOM 节点创建 React 组件

**方案**：
```tsx
// 改动前：递归每个节点
function renderChildNodes(parent) {
  return children.map(child => <RenderReactNode node={child} />);
}

// 改动后：只对可编辑块建组件
function renderOptimized(parent) {
  // 静态 HTML 一次挂载
  const staticHtml = extractStaticHtml(parent);
  // 可编辑块用 Portal
  const editableBlocks = extractEditableBlocks(parent);

  return (
    <>
      <div dangerouslySetInnerHTML={{ __html: staticHtml }} />
      {editableBlocks.map(block => (
        <EditableBlockPortal key={block.idx} {...block} />
      ))}
    </>
  );
}
```

**预期**：`RenderReactNode` 调用从数千 → 数十

### 9.3 Web Worker 统一卸载

**方案**：所有 MJML 编译移到 Worker

```ts
// mjmlWorker.ts
const compileQueue: Map<string, { resolve, reject }> = new Map();

self.onmessage = async (e) => {
  const { id, mjmlString, mode } = e.data;
  try {
    const html = mjml(mjmlString).html;
    self.postMessage({ id, html, success: true });
  } catch (error) {
    self.postMessage({ id, error: error.message, success: false });
  }
};

// 主线程
export function compileMjmlAsync(mjmlString: string): Promise<string> {
  const id = generateId();
  return new Promise((resolve, reject) => {
    compileQueue.set(id, { resolve, reject });
    worker.postMessage({ id, mjmlString });
  });
}
```
